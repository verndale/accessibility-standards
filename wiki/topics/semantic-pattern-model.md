# Semantic and pattern model

Semantics own atomic platform and WCAG obligations. Patterns reference semantic IDs, then add activation facts, interaction behavior, product choices, Functional Spec bindings, implementation outcomes, and proof routes. This prevents consumers from carrying divergent copies of the same rule.

The validated applicability matrix evaluates typed facts with only six operators. Trigger and resolution states distinguish what has been observed from what still requires product input. Standards-owned consequences resolve automatically. Form presence selects `pattern.field`; the independent `component.has_validation` fact selects `pattern.validation`, so inactive validation produces no boilerplate. Schema 3 replaced a fixed row-count guard with reachability and unused-fact invariants. Schema 4 adds closed string-enum domains: observed values and expressions outside a domain fail, and enum discriminators require exact `equals` rather than substring `contains`.

Every semantic and pattern carries normalized standards references with authority, identifier, URL, normative status, and a WCAG level where applicable. The 55-entry WCAG 2.2 Level A/AA inventory now classifies all 55 criteria as covered, with no partial or gap entries, and requires every semantic mapping to have a matching normative reference. Coverage is granted only through semantic mappings; pattern references record provenance without independently changing criterion status. The additive `3.1.0` phase introduced 21 dedicated rules across visual presentation, navigation and focus, pointer and input behavior, language, timing, and context-change consistency. The `3.2.0` phase adds 18 criterion-specific rules to complete the inventory while retaining every prior mapping. Its hybrid applicability model reuses broad non-text, page-context, rendered-interface, and form-field triggers while adding seven precise media and user-information facts. Missing facts require input, false facts skip their rows, and invalid facts fail validation.

Schema 4 contains 79 semantic records, 34 pattern contracts, and explicit coverage for all 30 current APG pattern-index entries and all seven Practices entries. Feed, grid, treegrid, meter, toggle button, and window splitter now have dedicated contracts; button, breadcrumb, landmarks, link, and table use composed or native semantic coverage where a custom widget would be wrong. Eleven cross-cutting contracts cover accessible descriptions, busy state, collection metadata, composite focus, current/pressed/sort states, disabled/read-only and hidden/inert behavior, range values, and presentational roles. Existing patterns were strengthened for complete keyboard, focus, ownership, state, live-update, and native-first behavior. Grid and treegrid are interactive composites and never replace a static data table; no current APG entry is deferred.

The APG inventory is exact and ordered. Each entry maps to existing pattern/semantic records, includes every record that directly cites the entry, and preserves a canonical source trace. Future APG entries may be recorded as deferred until the canonical inventory is upgraded, but an entry already present in the schema-4 inventory cannot be deferred simultaneously.

Canonical UI names enter through the [UI pattern binding](./ui-pattern-bindings.md), never through alias text or arbitrary Markdown. The binding resolves each ordered UI Design Brain slug exactly once to direct patterns, fact-dependent candidates, or baseline-only handling. Pattern activations consume derived accessibility pattern IDs; `component.pattern` is not a supported fact.
